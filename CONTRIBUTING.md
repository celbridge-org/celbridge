# Contributing to Celbridge

<!-- Q: What is this page for? -->

Thanks for your interest in Celbridge. This page explains the ways you can contribute to the project.

## Share what you build

<!-- Q: What's the best way to contribute to the Celbridge project? -->

The best way to contribute to Celbridge is to share what you build with the community.

<!-- Q: What could I share, and how? -->

If you use Celbridge to build a cool level editor, an image editing utility or a fun game, post a screenshot on the [community forum](https://celbridge.discourse.group/), share your project online and invite people to check it out.

<!-- Q: Why should I share it? -->

It's a great way to get feedback on your work and it helps spread the word about Celbridge too.

## Ask questions

<!-- Q: Where do I ask a question? -->

Ask questions on the [community forum](https://celbridge.discourse.group/), join in with discussions, and share your knowledge and expertise with others.

## Bug reports

<!-- Q: I've found a bug. How do I report it so it gets fixed? -->

Report a bug by [opening an issue](https://github.com/celbridge-org/celbridge/issues/new/choose). Search for existing issues first, and add to the existing ticket instead of opening a new one if you can.

<!-- Q: What should a bug report include? -->

A useful report has:

- The Celbridge version.
- Your operating system and its version (e.g. Windows 11 Pro 25H2).
- The steps that make the problem happen, starting from opening Celbridge.
- What you expected to happen, and what happened instead.
- If the problem is visible, a screenshot or video is very helpful.
- The log file from the run where it happened.

<!-- Q: Where do I find the log file? -->

File > Show Log opens the folder that holds the log files, with the current run's log selected:
  - Windows: `%LOCALAPPDATA%\Packages\org.celbridge.Celbridge_f09fs4qsgr17a\LocalState\Logs`
  - macOS: `~/Library/Application Support/Celbridge/Logs`

## Feature requests

<!-- Q: How do I ask for a new feature? -->

Start by posting your idea on the [community forum](https://celbridge.discourse.group/). Someone may already have a solution or a workaround, and the discussion can show whether the idea would work as a custom editor or utility, or if it needs new core functionality in Celbridge itself.

<!-- Q: Is a feature request the best way to get what I need? -->

If the feature could be implemented as a custom editor or utility, building it yourself is the quickest way to get it.

<!-- Q: Which feature requests help most? -->

The most useful feature requests for Celbridge itself are for things that extensions can't do yet.

<!-- Q: When should I open an issue? -->

If the feature does need a change to the Celbridge application, [open an issue](https://github.com/celbridge-org/celbridge/issues/new/choose). Please describe the problem that the feature would solve, and link to the forum discussion if applicable.

## Pull requests

<!-- Q: Can I contribute code to Celbridge? -->

The core application is developed and maintained by a small team. We don't take public pull requests, but we do welcome well written bug reports and feature requests, and we're always happy to discuss ideas for new features on the community forum.

<!-- Q: Why don't you take pull requests? -->

Our philosophy is to keep the core Celbridge application small and tightly defined so that our small team can continue to maintain the project as it grows. Rather than bloating Celbridge with too many core features, we want to enable the community to add new features to Celbridge via extensions that you develop and share however you like.

<!-- Q: What if I've worked out how to fix a bug? -->

If you've tracked down the cause of a bug or worked out a fix, please let us know by submitting a bug report. Code snippets of your proposed solution are welcome, and they're often the quickest way to get a bug fixed.
